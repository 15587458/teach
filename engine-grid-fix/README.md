# engine-grid-fix

Утиліта для Мака: заново знаходить біти в **усіх** треках бібліотеки Engine DJ і переписує сітку (beatgrid) прямо в базу Engine. Для кожного треку темп визначається окремо, тому діапазон BPM вручну задавати не треба. Пульт (SC Live 4, Engine OS 5.3.0) показує нову сітку на штатному екрані, прошивку ніхто не чіпає.

## Що робить

1. Читає бібліотеку: `~/Music/Engine Library/Database2/m.db` на Маку або `Engine Library` на флешці.
2. Для кожного треку знаходить біти, рахує точний BPM, ставить сітку на атаку удару (точність до кількох мс) і вибирає перший удар такту.
3. **Нічого не записує, поки ти не скажеш.** Перший запуск лише аналізує і створює звіт `gridfix-report.csv`: старий BPM, новий BPM, наскільки була зсунута сітка, і що утиліта збирається зробити.
4. З `--apply` робить резервну копію бази і записує нові сітки. Виправлені сітки блокуються (`isBeatGridLocked`), щоб Engine не переаналізував їх назад.

Утиліта **не чіпає**:
- треки, сітку яких ти вже заблокував в Engine;
- треки з нерівним темпом (живі барабани, зміни темпу). Вони йдуть у звіт з позначкою `manual`;
- треки, дані яких мають незнайомий формат. Перед записом утиліта перевіряє, що вміє байт-у-байт прочитати і відтворити наявні дані треку.

## Встановлення на Мак

```bash
# 1. Python 3.10+ (якщо немає): https://www.python.org/downloads/macos/
# 2. У папці цього проєкту:
cd engine-grid-fix
python3 -m venv .venv
source .venv/bin/activate
pip install .
```

## Використання

**Перед запуском закрий Engine DJ Desktop.** Програма тримає базу відкритою.

```bash
source .venv/bin/activate

# Спробувати на перших 20 треках (нічого не пише)
engine-grid-fix --limit 20

# Вся бібліотека, тільки звіт (1000 треків займе кілька десятків хвилин)
engine-grid-fix

# Переглянути gridfix-report.csv (відкривається в Numbers/Excel), потім записати:
engine-grid-fix --apply
```

Повторний запуск не аналізує треки заново: результати зберігаються в `gridfix-cache.json` поряд із базою.

Після `--apply` відкрий Engine DJ Desktop, перевір кілька треків і синхронізуй флешку. Сітки поїдуть на пульт.

Можна працювати і прямо з флешкою:
```bash
engine-grid-fix --library "/Volumes/НАЗВА_ФЛЕШКИ/Engine Library" --apply
```

### Параметри

| Параметр | Що робить |
|---|---|
| `--library ПАПКА` | папка `Engine Library` (за замовчуванням `~/Music/Engine Library`) |
| `--apply` | записати зміни (без нього лише звіт) |
| `--limit N` | тільки перші N треків |
| `--jobs N` | скільки ядер використовувати |
| `--min-confidence 0.7` | нижче цього порогу трек вважається треком з нерівним темпом і не змінюється |
| `--include-locked` | змінювати і заблоковані сітки |
| `--no-lock` | не блокувати виправлені сітки |
| `--backend beat_this` | нейромережевий детектор (експериментально, див. нижче) |

### Відкат

Перед кожним записом утиліта кладе копію бази в `Database2/backup-gridfix-ДАТА/`. Щоб відкотити зміни, закрий Engine DJ і скопіюй `m.db` з цієї папки назад у `Database2/`.

## Відомі обмеження

- **Перший удар такту.** Детектор librosa шукає його за найсильнішим басом. Темп і попадання в біт він визначає точно, але номер долі в такті іноді може бути зсунутий на 1–3 долі. Детектор `beat_this` має визначати такт краще, але з цією утилітою він ще **не тестувався**. Встановлення: `pip install torch "beat_this @ git+https://github.com/CPJKU/beat_this.git"`, запуск: `--backend beat_this`.
- Сітка завжди з постійним темпом, як і сітка самого Engine.
- Формат бази взято з відкритого проєкту [libdjinterop](https://github.com/xsco/libdjinterop). Утиліту перевірено на тестовій базі того самого формату, але ще не на справжній базі з Engine DJ 4.x. Тому спочатку запускай з `--limit 20`, і `--apply` лише після перевірки звіту.
